# Спецификации FormFlow

Каталог документации FormFlow. Используй таблицу как карту источников истины: не копируй одно правило в несколько документов.

| Тема | Канонический источник |
| --- | --- |
| HTTP-маршруты, JSON-запросы и ответы, ошибки и транспортная авторизация | [Контракт HTTP API](api/openapi.yaml) |
| Модули, архитектура, межмодульные границы и технические механизмы | [Архитектура и размещение кода](architecture.md) |
| Последовательность и развилки бизнес-сценариев | Mermaid-диаграмма сценария в соответствующем документе [бизнес-логики](business-logic/overview.md); без копии того же правила в дополнительной прозе |

| Документ | Назначение |
| --- | --- |
| [План подготовки к запуску](launch-checklist.md) | Планируемые работы, зависимости, подробные чек-листы приёмки и журнал выполнения; не заменяет спецификации реализованного поведения. |
| [Бизнес-логика: обзор сценариев](business-logic/overview.md) | Навигация и общая карта сценариев; не дублирует детали сценариев. |
| [Вход и ограничение попыток](business-logic/identity.md) | Mermaid-диаграмма сценария Identity. |
| [Workspace, участники и доступ](business-logic/tenancy.md) | Mermaid-диаграммы сценариев Tenancy. |
| [Проекты, формы и поля](business-logic/form-definition.md) | Mermaid-диаграмма сценария FormDefinition. |
| [Отправленные ответы](business-logic/submissions.md) | Mermaid-диаграммы сценариев Submissions. |
| [Архитектура и размещение кода](architecture.md) | Текущая структура и согласованные правила: слои, публичные контракты модулей, события, согласованность и расширяемость. |
| [Контракт HTTP API](api/openapi.yaml) | OpenAPI: операции, схемы запросов и ответов, ошибки и примеры. |

В диаграммах различай текущее поведение (`as-is`), согласованное целевое поведение и открытые вопросы. Не представляй планируемое как реализованное. Для бизнес-правила поддерживай одну диаграмму-владельца; другие документы ссылаются на неё.
